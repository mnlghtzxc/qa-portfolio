# Тестирование REST API на JSON Server

## Цель проекта

Практика тестирования REST API и автоматизации проверок в Postman. Проект включает позитивные и негативные сценарии для CRUD-операций, а также проверку серверной валидации входных данных.

## Особенности проекта

* Полный E2E CRUD-сценарий:

  POST → GET → PUT → PATCH → DELETE

* ID созданного объекта автоматически сохраняется в переменную окружения `currentPostId`.

* Последующие запросы используют сохранённый ID.

* После завершения сценария переменная очищается.

* Используются автоматические проверки через `pm.test()` и `pm.expect()`.

## Покрытие

| Метод  | Позитивные                     | Негативные                                            |
| ------ | ------------------------------ | ----------------------------------------------------- |
| GET    | Получение списка и поста по ID | Несуществующий ID                                     |
| POST   | Создание поста                 | Пустое тело, отсутствие полей, неверные типы данных   |
| PUT    | Полное обновление              | 404, отсутствие обязательных полей, невалидные данные |
| PATCH  | Частичное обновление           | 404, пустой запрос, null, неверные типы               |
| DELETE | Удаление поста                 | Удаление несуществующего объекта                      |

### Проверка валидации

**Title**

* пустая строка;
* пробелы;
* число;
* null;
* отсутствие поля.

**Body**

* пустая строка;
* пробелы;
* число;
* null;
* отсутствие поля.

**UserId**

* 0;
* отрицательное число;
* дробное число;
* строка;
* null;
* отсутствие поля.

## Автоматические проверки

В тестах проверяются:

* HTTP-статусы;
* Content-Type;
* структура ответа;
* типы данных;
* обязательные поля;
* сообщения об ошибках;
* корректность CRUD-операций.

## Запуск проекта

```bash
git clone <repository-url>
cd qa-api-lab

npm install

node server.js
```

После запуска сервер будет доступен по адресу:

```text
http://localhost:3000
```

Импортировать коллекцию и окружение в Postman, затем запустить Collection Runner.
