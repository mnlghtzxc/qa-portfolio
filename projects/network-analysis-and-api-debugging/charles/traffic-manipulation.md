#  Charles Proxy: модификация трафика и эмуляция ошибок

## 🎯 Цель
Проверить устойчивость клиентского приложения к нештатным ситуациям на серверной стороне путём перехвата и модификации HTTP-трафика.

## 🧠 Ключевые навыки
- Перехват и расшифровка HTTPS-трафика (SSL Proxying)
- Модификация запросов на лету (Breakpoints)
- Автоматическая подмена заголовков и статусов (Rewrite Rules)
- Симуляция серверных ошибок (5xx)
- Подмена ответов сервера локальными данными (Map Local)

## 🛠️ Инструменты
- **Charles Proxy**
- **Тестовое окружение:** JSONPlaceholder API

## 🧪 Выполненные сценарии

### 🔐 SSL Proxying
Перехват и расшифровка HTTPS-трафика для анализа в Charles.
**Результат:** зашифрованный трафик успешно расшифрован, доступны все детали запросов и ответов.
![SSL Proxying](./screenshots/ssl-proxying.png)

### 🛑 Breakpoint (модификация запроса)
Изменение параметров запроса до отправки на сервер.
**Результат:** запрос перехвачен, параметры модифицированы, сервер обработал изменённый запрос.
![Breakpoint](./screenshots/breakpoint-modification.png)

### ✏️ Rewrite Headers
Добавление кастомного заголовка `X-QA-Test` ко всем запросам.
**Результат:** заголовок добавлен, API приняло запрос с дополнительным заголовком.
![Rewrite Headers](./screenshots/rewrite-headers.png)

### 💥 Rewrite Status Code
Изменение статуса ответа с `200 OK` на `503 Service Unavailable`.
**Результат:** клиент получил ошибку сервера, проверена реакция приложения на недоступность бэкенда.
![Status Code Rewrite](./screenshots/status-code-change.png)

### 📁 Map Local
Подмена ответа сервера локальным JSON-файлом. Позволяет имитировать:
- Недоступность API
- Кастомные или некорректные данные
- Отсутствие обязательных полей
**Результат:** ответ сервера полностью заменён локальным файлом, приложение получило подставные данные.
![Map Local](./screenshots/map-local-response.png)

## 🧪 Как я применяю это в тестировании
1. **Проверка обработки ошибок:** через Rewrite Status меняю 200 на 503 или 502 и смотрю, показывает ли фронт понятное сообщение или падает.
2. **Тестирование граничных данных:** через Map Local подменяю ответ на JSON с отсутствующими полями, null-значениями или очень длинными строками — проверяю, не ломается ли парсинг.
3. **Имитация медленной сети:** через Breakpoints или Throttle задерживаю ответ и проверяю таймауты, индикаторы загрузки.
4. **Проверка авторизации:** через Rewrite удаляю или изменяю токен в заголовках и смотрю, как API и клиент обрабатывают ошибку аутентификации.
