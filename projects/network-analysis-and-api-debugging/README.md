#  Анализ и отладка клиент-серверного взаимодействия

## 🎯 Цель
Продемонстрировать навыки анализа HTTP/HTTPS-трафика, локализации дефектов на стыке фронтенда и бэкенда, а также модификации запросов/ответов для тестирования нештатных ситуаций — с помощью Chrome DevTools и Charles Proxy.

## 🧠 Ключевые навыки
- Фильтрация XHR/Fetch-запросов во вкладке Network
- Чтение и интерпретация HTTP-заголовков, статусов, тел ответов
- Анализ параметров производительности и кэширования
- Локализация проблем: frontend vs backend vs сеть
- Экспорт и чтение HAR-файлов
- Перехват и расшифровка HTTPS-трафика (SSL Proxying)
- Модификация запросов/ответов через Breakpoints, Rewrite Rules
- Подмена ответов сервера локальными данными (Map Local)
- Эмуляция серверных ошибок и проверка устойчивости клиента

## 🛠️ Инструменты
- **Chrome DevTools** (вкладка Network)
- **Charles Proxy** (SSL Proxying, Breakpoints, Rewrite, Map Local)
- **Тестовое окружение:** JSONPlaceholder API

## 🧪 Как я применяю это в тестировании
1. **Анализ инцидента:** если пользователь сообщает об ошибке, открываю DevTools Network, ищу упавший запрос, смотрю статус, тело, заголовки — сразу понимаю, проблема на фронте (данные не обработались) или на бэкенде (вернулась ошибка).
2. **Проверка обработки ошибок:** через Charles Rewrite меняю статус 200 на 503 и смотрю, как фронтовое приложение показывает ошибку — не падает ли, выводит ли понятное сообщение.
3. **Тестирование без реального бэкенда:** через Map Local подменяю ответ API кастомным JSON, чтобы проверить, как интерфейс реагирует на отсутствие данных, null-поля или очень длинные строки.
4. **Воспроизведение сетевых проблем:** через Charles Throttle или Breakpoints имитирую медленное соединение или зависший ответ, проверяю таймауты и индикаторы загрузки.

## 📌 Примечание
Проект фиксирует практическое владение инструментами анализа трафика. В будущем планирую дополнить его более детальными отчётами о найденных багах и аналитическими выводами по каждому сценарию.
