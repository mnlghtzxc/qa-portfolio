# Тестирование сервиса доставки «Яндекс Самокат» (веб + мобильное API)

## 🎯 Цель
Продемонстрировать комплексное тестирование коммерческого продукта: фронтенд (валидация, бизнес-логика, вёрстка), бэкенд (REST API, контракты), мобильное приложение курьера и проверки целостности данных через SQL.

## 📦 Что тестируем
- **Веб-приложение** заказа самокатов: экран оформления, статус заказа.
- **Мобильное приложение курьера** (Android, `scooter-v2.0.apk`): авторизация, список заказов, принятие/завершение.
- **API**: создание/удаление курьера, получение заказа по треку.
- **База данных**: PostgreSQL, проверка корректности удаления/обновления данных.

## 🧪 Особенности тест-дизайна
- **Декомпозиция на пользовательские сценарии**: заказчик (веб) → курьер (мобильное) → система (API+БД).
- **Классы эквивалентности и граничные значения** для каждого поля ввода (подробная матрица валидации).
- **Проверка контрактов API**: сопоставление документации, реального поведения и кодов ошибок.
- **Анализ целостности данных**: SQL-запросы после критических операций (удаление курьера, отмена заказа).
- **Кросс-браузерное тестирование**: Google Chrome, Яндекс.Браузер.

## 📊 Покрытие

### Веб-приложение (фронтенд)
| Экран              | Позитивные сценарии                    | Негативные / граничные                                                                 | Статус |
|--------------------|----------------------------------------|----------------------------------------------------------------------------------------|--------|
| Статус заказа      | Поиск, отображение статусов, верстка   | Несуществующий номер, длинные строки, кнопка «Отменить» активна на всех статусах       | Done   |
| Форма заказа       | Валидные данные                        | Имя с дефисом, адрес вне границ, телефон без префикса, пустая дата, комментарий >24   | Done   |

### Мобильное приложение (Android)
| Функция            | Позитивные сценарии                                | Негативные / граничные                                                   | Статус |
|--------------------|----------------------------------------------------|--------------------------------------------------------------------------|--------|
| Авторизация        | Валидный логин/пароль                             | Невалидные символы, длина, пустые поля                                   | Done   |
| Список заказов     | Pull-to-refresh, фильтр, принятие/завершение       | Приём чужого/отменённого заказа, анимация, синяя точка, поведение без сети | Done   |
| Нотификации        | Уведомление за 2 часа, переход по нему            | Уведомления при выгруженном приложении, запрете уведомлений, блокировке  | Done   |

### API
| Метод                      | Позитивные сценарии                | Негативные / граничные                                            | Статус |
|----------------------------|------------------------------------|-------------------------------------------------------------------|--------|
| POST /api/v1/courier       | Создание курьера                   | Невалидные логин/пароль/имя, дубликат, отсутствие обязательных полей | Done   |
| DELETE /api/v1/courier/:id | Удаление курьера                   | Отсутствие id, несуществующий id, каскадное удаление заказов      | Done   |
| GET /api/v1/orders/track   | Получение заказа по треку          | Несуществующий трек, запрос без трека                              | Done   |

## 🐞 Ключевые баги (из 30+)

| MV8-104 | Отменённый заказ не удаляется из списка после pull-to-refresh  | High        |
| MV8-121 | POST /api/v1/courier создаёт курьера с кириллицей в логине    | High        |
| MV8-139 | DELETE /api/v1/courier не удаляет связанные заказы             | High        |
| MV8-106 | Карточка заказа не переключается в полную версию тапом         | Medium      |
| MV8-129 | Длинное имя курьера ломает вёрстку на экране статуса           | Medium      |
