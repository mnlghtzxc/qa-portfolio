# Наблюдения и рекомендации — Cinema Ticket Purchase API

В ходе тестирования API критических багов не обнаружено: бизнес-логика работает в соответствии с требованиями, все ограничения целостности соблюдены.  
Ниже перечислены наблюдения, которые не являются багами в рамках учебного проекта, но могут быть полезны при дальнейшем развитии системы.

| ID | Описание | Серьёзность | Рекомендация |
|---|---|---|---|
| 1 | **Фильтрация по movie_id и date не реализована.** Параметры заявлены в документации, но API их игнорирует. | Средняя | Реализовать фильтрацию или убрать параметры из документации. |
| 2 | **Отсутствует пагинация.** При большом количестве сеансов ответ может быть слишком объёмным. | Низкая | Добавить параметры `limit` и `offset`. |
| 3 | **Валидация email на уровне API не выполняется.** Клиент может передать строку без `@`, и база примет её (ограничение только на уникальность). | Низкая | Добавить проверку формата email перед сохранением. |
| 4 | **Цена билета копируется из зала.** При изменении `base_price` зала цена уже проданных билетов не меняется. | Низкая | Рассмотреть возможность хранения ссылки на цену (через `hall_id`) или явно документировать такое поведение. |
| 5 | **Отсутствует подтверждение email при анонимной покупке.** Один и тот же email может быть использован многократно разными покупателями. | Низкая | Рассмотреть отправку кода подтверждения или привязку номера телефона. |

Все перечисленные пункты носят рекомендательный характер и не влияют на корректность текущей версии API.
