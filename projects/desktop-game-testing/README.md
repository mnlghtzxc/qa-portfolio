# Исследовательское тестирование 3D-шутера kkrieger-beta

## 🎯 Цель
Показать навыки исследовательского тестирования в условиях полного отсутствия спецификации: декомпозиция систем, поиск уязвимых стыков, оформление багов и формулировка root cause без доступа к исходному коду.

## 📦 Что тестируем
Автономный 3D-шутер от первого лица под Windows (сборка `kkrieger-beta`). Процедурная генерация уровней, 5 видов оружия, враги с простым ИИ, телепортация по контрольным точкам, интерактивные двери, сбор предметов (здоровье, боеприпасы, оружие).  
**Управление:** WASD + Space (прыжок), мышь (камера, стрельба), 1–5 (оружие), M1–M9 (телепортация), Esc (меню).

## 🧠 Декомпозиция систем

Перед тестированием игра была разбита на 13 систем:
`Передвижение` • `Стрельба` • `Урон` • `Подбор предметов` • `Переключение оружия` • `HUD` • `Враги (AI)` • `Двери` • `Коллизии` • `Телепортация` • `Аудио` • `Камера` • `Меню`

Особое внимание уделялось **стыкам систем**:
- Анимация дверей vs коллизия игрока и врагов
- Удержание огня vs переключение оружия
- Прыжок vs смена оружия
- AI врагов vs открытое меню (пауза)

## 🧪 Примеры root cause анализа

**BUG-01 (Прохождение сквозь дверь):**  
Состояние коллизии двери («открыто») включается по срабатыванию триггера, а не по окончании анимации открытия. Игрок успевает пройти до завершения визуального открытия.  
*Стык:* Анимация ↔ Коллизия.

**BUG-05 (Застревание врага в «Корнях»):**  
Навигационная сетка (NavMesh) не учитывает вогнутую форму объекта. Алгоритм обхода препятствий не справляется, враг упирается в геометрию.  
*Стык:* AI ↔ Коллизия.

**BUG-07 (Прекращение стрельбы при смене оружия):**  
Состояние удержания ЛКМ не передаётся новому оружию — система ожидает нового нажатия. Одиночный выстрел происходит из-за остаточного кадра ввода.  
*Стык:* Ввод ↔ Оружие.

## 🧰 Инструменты
Ручное тестирование, OBS (видеозапись багов), мониторинг процессов (зависания, утечки), Event Viewer (системные логи Windows).
