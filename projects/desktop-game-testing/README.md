# Desktop Game Testing

# Исследовательское тестирование 3D-шутера (kkrieger-beta)

Передо мной была сборка автономного шутера от первого лица под Windows — без документации, без требований, только билд. Процедурная генерация контента, 5 видов оружия, враги с простым ИИ, управление с клавиатуры и мыши. Задача — провести исследовательское тестирование и найти баги, влияющие на играбельность, стабильность и взаимодействие систем.

## Как строил тестирование
Поскольку спецификации не было, опирался на ожидаемое поведение игровых механик и здравый смысл. Разбил игру на системы: передвижение, стрельба, смена оружия, подбор предметов (здоровье, патроны), телепортация, поведение врагов, двери с триггерами, коллизии, камера, меню. Особое внимание — стыкам систем: например, что будет, если переключать оружие в прыжке или держать огонь при смене оружия. Проверял, как анимации взаимодействуют с физическими коллайдерами, как AI обходит препятствия.

## Примеры найденных багов (всего 10)

**Зависание при Alt+Tab в полноэкранном режиме**
- Серьёзность: Критическая (игра перестаёт отвечать)
- Шаги: запустить игру в fullscreen, нажать Alt+Tab.
- Фактический результат: игра зависает, процесс не отвечает.
- Ожидаемый результат: игра сворачивается и восстанавливается без сбоя.
- Root cause: отсутствует обработка потери/восстановления графического контекста DirectX — нет перезагрузки ресурсов при сворачивании.

**Прохождение сквозь дверь во время анимации открытия**
- Серьёзность: Средняя
- Шаги: подойти к двери, активировать триггер открытия, в момент начала анимации пройти вперёд.
- Фактический результат: персонаж проходит сквозь дверь до завершения анимации.
- Ожидаемый результат: коллизия блокирует проход до полного открытия.
- Root cause: состояние коллизии («открыто») включается по срабатыванию триггера, а не по окончании анимации. Синхронизация анимации и физики отсутствует.

**Застревание врага в объекте «Корни»**
- Серьёзность: Высокая (ломает геймплей)
- Шаги: спровоцировать врага, завести его за объект «Корни» так, чтобы он попытался обойти препятствие.
- Фактический результат: враг застревает в геометрии, преследование прекращается.
- Root cause: навигационная сетка (NavMesh) не учитывает вогнутые формы объекта, алгоритм обхода не справляется.

**Прекращение стрельбы после смены оружия при удержании ЛКМ**
- Серьёзность: Средняя
- Шаги: зажать левую кнопку мыши (огонь), не отпуская, переключить оружие клавишами 1–5.
- Фактический результат: происходит одиночный выстрел, стрельба прекращается.
- Ожидаемый результат: стрельба продолжается с новым оружием.
- Root cause: состояние удержания кнопки не передаётся новому оружию, система ждёт нового нажатия.

## Общие выводы
Нашёл и оформил 10 багов, большинство — стабильные. Основная масса дефектов связана с:
- расхождением визуального отображения и физической модели (двери, колонны);
- обработкой состояний ввода (игнорирование удержания клавиш после смены оружия, задержки в прыжке);
- ИИ и навигацией (застревание в геометрии, движение врагов при вызове меню);
- стабильностью (отсутствие устойчивости к системным событиям).

Этот проект показывает, как я тестирую без готовых требований: выделяю системы, ищу уязвимые стыки, формулирую root cause без доступа к коду. Именно такой подход востребован в GameDev, где спецификации часто ограничены, а продукт нужно оценивать целиком.
